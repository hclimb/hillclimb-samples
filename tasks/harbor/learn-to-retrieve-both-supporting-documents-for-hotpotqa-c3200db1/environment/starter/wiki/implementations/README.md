# Implementations

The record of how each code / feature / codebase change was designed, built, integrated, and
tested: the motivation, the options weighed and their tradeoffs, the approach chosen, what it
touched, and the test results. One file per non-trivial change.

This is *not* where "how it works now" lives — that belongs in the reference pages
([architecture](../architecture/README.md), [data](../data/README.md),
[evaluation](../evaluation/README.md), [training](../training/README.md),
[infrastructure](../infrastructure/README.md)), which you update **in the same change**. An implementation
note is change-scoped and dated: it records *why this change was made, what it did, and what we
already tried*, so the reference pages can stay lean and current.

**Append-only.** Notes are dated and never rewritten; if a later change reverses an earlier one,
write a *new* note that supersedes it (link back with a relative link).

## Conventions

- **Filename:** `YYYY-MM-DD-short-slug.md` (e.g. `2026-07-15-gqa-per-kv-head-bank.md`).
- Cover what [`GUIDELINES.md`](GUIDELINES.md) lists.
- Add a row to the index below and link the reference page(s) you updated.
