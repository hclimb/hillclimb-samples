# Experiments

Hypothesis-driven experiment write-ups. One file per experiment (or per tightly-related sweep).
Each answers, unambiguously: **what did we think, what did we run, what happened, and what do we
now believe.** A colleague who never saw the run should be able to reproduce it and reach the
same conclusion from the doc alone.

**Append-only.** Experiments are dated and never rewritten. A follow-up or correction is a *new*
file that links back to the one it revises (see `corpus_sweep_results.md` →
`corpus_sweep_corrected.md` at the repo root for the pattern this replaces).

## Conventions

- **Filename:** `YYYY-MM-DD-short-slug.md` (e.g. `2026-07-15-corpus-grounding-sweep.md`).
- Cover what [`GUIDELINES.md`](GUIDELINES.md) lists.
- **Results are git-friendly:** metrics/tables live *in the doc* (Markdown) or as committed
  CSV/JSON. Large artifacts are pointers, never committed binaries —
  - plots → `results/figures/…` (commit the `.png` only if small and central),
  - raw dumps / checkpoints → `gs://…`,
  - training/eval curves → **wandb** run URL/ID.
- **Repro block is mandatory** (command + overrides, commit SHA, checkpoint path, wandb run,
  TPU type). The resolved config is also in each checkpoint's `.hydra/config.yaml`.
- Add a row to the index below.
